# Figma Screen

## What this step is for

This is where the design gets real. You're creating (or revising) a screen that looks like the actual product — using real components, real content, and the existing visual system. This isn't a wireframe or a sketch. It's what the thing should actually look like.

## How to think through it

1. Look at nearby frames and the existing visual system. What patterns are already established?
2. Identify reusable components, styles, typography, spacing, and interaction patterns.
3. Define the screen's purpose and its primary action.
4. Create or revise the screen, staying within the existing design direction wherever possible.
5. Include required states if they're relevant to the task.
6. Add concise labels or annotations only if the board needs them for clarity.

## Design guidelines

- Use the product's existing components and visual language first. Don't invent new patterns when established ones work.
- Don't redesign the whole product unless that's what was asked for.
- Keep the screen focused on the user's next action. Everything on screen should support that.
- Use realistic content — real names, real numbers, real copy. "Lorem ipsum" is a missed opportunity.
- Make hierarchy and interaction states clear at a glance.
- Design empty, loading, error, and success states when they affect how the user experiences the task.
- The screen should be understandable without someone standing next to it explaining what it does.

## Ground rules

- If you're writing directly into Figma, follow the Figma tool workflow for file context.
- If you're only describing the screen, provide a plan specific enough to build from.
- Skip purely decorative changes unless they improve comprehension, trust, or whether the user can complete their task.
